# vrs-model — звідки беруться відсотки інвайтів на мейджор

Тут рахується все, що показує сторінка `/major`: скільки очок VRS має команда,
скільки ще може набрати до відсічення і з якою ймовірністю опиниться в межах
регіональної квоти. Сайт сам нічого не рахує — він читає дві таблиці з бази,
які заповнює цей конвеєр.

## Конвеєр: три кроки

```
engine-all.mjs      симуляція → розподіл очок по кожній команді
      ↓
publish-all.mjs     → final15.json  (готові рядки для бази)
      ↓
push-major2.mjs     → major_projection + major_meta у Supabase
```

Запуск звичайного дня:

```bash
node engine-all.mjs 40000     # подивитись на результат
node publish-all.mjs          # зібрати final15.json
node push-major2.mjs          # пробний прогін, нічого не пише
node push-major2.mjs --apply  # залити
```

`push-major2.mjs` читає ключ із `../.env.local` сайту — у репозиторії його
немає і бути не повинно.

## Чим живиться

Усе — з HLTV, не з відкритого репозиторію Valve: там інші цифри й інші склади.

- **`vrs-details/*.json`** — повний розклад очок по кожній із 36 команд, зі
  сторінки `/valve-ranking/teams/details/...`. Формат:
  `{n, p, c:[LAN, мережа, гроші, скальпи, H2H], L, O, C, N}`, де `c` — підсумки
  компонентів із шапки сторінки, а `L/O/C/N` — рядки з датами й очками.
  Інваріант, який має виконуватись завжди: `400 + Σc === p`, до одиниці.
- **`eu-2810.json` / `am-2810.json` / `as-2810.json`** — три регіональні
  таблиці. Саме вони, а не глобальна: інвайти роздаються по регіонах, і склад
  із очками там інші. Назви файлів історичні, всередині — свіжий зліп.
- **`fresh/details-*.json`** — зліпки розкладів за день, як їх зняли.
  `apply-fresh.mjs` розкладає зліпок по `vrs-details/` з перевіркою сум, а
  старе кладе в `fresh/backup-*/`.

## Формула

Повністю описана в пам'яті проєкту (`vrs-formula-published`), коротко:

```
VRS = 400 + LAN wins + Opp. network + Bounty offered + Bounty collected + H2H
LAN wins       = Σ 47·recency по десяти НАЙСВІЖІШИХ перемогах на ЛАНі
Bounty offered = 19,4 · (Σ призові·recency)^0,23        } десять найкращих
Bounty collect =  244 · (Σ bounty·recency·вага)^0,23    } у кожному,
Opp. network   =  100 · (Σ network·recency·вага)^0,23   } з витісненням
```

Два місця, де найлегше помилитись:

1. **Межа в десять рядків.** Команда, у якої всі десять ЛАН-перемог свіжі по 47,
   з наступної перемоги не отримує **нічого**. Саме тому 100 Thieves і Eternal
   Fire наприкінці жовтня рухались лише за рахунок призових.
2. **H2H перераховується від нової бази** і забирає назад більшу частину
   приросту: `ΔH2H ≈ пряма_передача − 0,56·Δбаза`. Константа `H2H_DAMP = 0,56`.

## Що ще лежить у теці

- `fnatic-watch.mjs`, `worth.mjs`, `gap.mjs`, `gap2.mjs`, `threshold.mjs`,
  `event-sim.mjs`, `place-to-major.mjs`, `pairs.mjs` — відповіді на питання
  «скільки дасть цей турнір», «що має статись, щоб пройшли двоє», «яке місце
  веде на мейджор».
- `fit-win.mjs`, `h2h-damp.mjs`, `decay-exact.mjs`, `drift-wide.mjs`,
  `band-tilt.mjs` — як міряли константи. Крива ймовірності перемоги
  `E = 1/(1 + 10^(0,9728·Δ/−817,4))` перевірена на 32 лініях букмекера.
- `liquipedia/` — кешовані сторінки турнірів, `reg/` — списки заявлених,
  `sim/` — старі прогони, `dent*.xlsx` — книга календаря.
- Купка одноразових скриптів (`at.mjs`, `chain*.mjs`, `dumps.mjs`,
  `extract*.mjs`, `build-inputs.mjs`) витягувала дані з журналу робочої сесії.
  Вони прив'язані до конкретної машини й уже нічого не відкривають — лежать
  як архів.
- `openvrs/` і `node_modules/` у гіт не їдуть (див. `.gitignore`): перше —
  чужий клон на пів гігабайта, яким конвеєр не користується, друге
  ставиться через `npm i`.

## Щоденна перевірка перед перерахунком

1. Таблиця запізнюється: переконайся, що зліп уже бачить учорашній день.
2. `400 + Σc === p` на всіх розкладах — `apply-fresh.mjs` це робить сам.
3. Однойменні рядки: у таблиці бувають дві «Chinggis Warriors» або дві
   «GamerLegion» (академія). Брати ту, що з потрібними очками, а не першу.
4. Календар звіряти з HLTV, а не лише з книгою: події зникають і додаються.
5. Друга заливка за день затирає базу для стрілок — тоді `KEEP_PREV=1`.
6. Перед `--apply` прогнати без нього й подивитись на список.
